# SeeMind 产品手册 V2：设计系统与样张实施计划

版本：2026-10-22 / D02 / 工作文件
状态：执行中（阶段 0 已审视现有 HTML 及 BP 素材；阶段 1 待确定可编辑画布接入）

## 1. 设计目标

从现有的“文字为主、示意界面”的 8 页 HTML 样稿，升级为专业产品手册。
交付重点不是代码，而是可直接审阅的逐页设计图、可编辑的原始设计文件、正式 PDF。
整套手册需在前两页解释“产品究竟是什么”，并用真实产品界面与业务场景说明能力。

## 2. 产品口径（以 BP 和既有评审结论为依据）

- 统一底座：SeeMind / World State。
- 三种产品形态：实时搜索、实时推荐、场景智能体。
- 可扩展的平台服务方向：World State API。接口范围与商业化状态需核实。
- 长期方向：面向 Physical AI 的外部世界状态与数据服务。不得写成已大规模交付的成熟产品。
- 应用场景：城市治理、文旅景区等；已实施、试点、演示和规划分别标识，不混淆。

## 4. 建议的设计语言

方向：明亮现代的科技产品编辑式画册（Editorial Tech）。

- 封面以真实生活世界的大幅摄影画面为主，叠加极轻薄、节制的状态信息；避免大面积深紫、黑蓝发光装饰。
- 内页采用暖白纸面、深石墨文本、少量品牌点缀色；以大小标题、整页照片、极少的图形语言建立节奏。
- 画面保持真实镜头感：自然光、城市空气透视、非完美的现实质感。交通/行人/空间结构必须合理。
- 对话/状态组件只作为证据或解释，保留可编辑层，不做厚边框和浮夸玻璃球装饰。
- 风格分为三种页面模板：A 摄影主视觉页；B 内容叙事页；C 产品截图 + 功能解剖页。整本手册交替使用，避免连续表格。
- 每页只讲一个主题，图优先、文案简短；原始技术主张不随意夸大。

## 5. 建议 12 页结构（第一版可伸缩）

| 页 | 标题 | 视觉重点 |
|---|---|---|
| 01 | 封面 · 让 AI 理解物理世界 | 大幅明亮真实世界影像 + 品牌 |
| 02 | 目录与产品全景 | 一眼区分 3 类产品、底座、API、长期方向 |
| 03 | SeeMind + World State | 多源世界状态到对外产品的精练结构图 |
| 04 | 实时搜索 | 一张实际问答/实时状态界面 + 生活场景 |
| 05 | 实时推荐 | 状态变化、方案对比和实时建议 |
| 06 | 场景智能体总览 | 应用角色、查询、判断、执行、验证 |
| 07 | 城市治理 | 真实城市画面 / 管理端界面 / 事件闭环 |
| 08 | 城市治理产品交互 | 问答 + 发现、派单、处置、核验的可读界面 |
| 09 | 文旅景区 | 实时停车、拥挤程度、线路等场景与真实界面 |
| 10 | World State API | 输入、标准化时空状态、输出接口示意，标注发展状态 |
| 11 | Physical AI 方向 | 汽车、机器人、无人机外部认知的方向性场景，明确阶段 |
| 12 | 部署、合作与封底 | 适用对象、落地路径、联系信息（待核实） |

以上是设计框架，不代表所列能力都已商业交付。具体发布稿以 BP、接口说明、项目资料再次核实。

## 6. 第一轮样张：只做 3 页

1. 封面：验证摄影风格、品牌气质、字体与留白。
2. 目录与产品全景：验证“是什么产品”的理解效率。
3. 业务场景代表页（优先城市治理）：验证照片、真实屏幕、简短卖点是否协调。

样张输出 3 张可直接查看的高分辨率图像，而不是让评审阅读 HTML 代码；在主画布中保留原生可编辑图层。
用户确认后再扩展完整 12 页。

## 8. 完成标准

- 翻到 P02：外部读者 10 秒内能复述产品分类及相互关系。
- 每页有一个视觉中心；字号在 A4 打印比例可辨，图片不失真。
- 真人/车辆/建筑/道路符合现实逻辑；产品 UI 不冒充未存在的功能。
- 所有数字、名称、产品阶段、案例落地状态有来源和负责人确认。
- 源文件、逐页预览图、正式 PDF 都能复用，保留 v1 历史版本，不覆盖。
